Reviewer Display Policy
Controls
V1 — Alias-only is locked. The display policy toggle governs future policy expansion only. In V1, reviewer identity is always aliased ({first_name} {last_initial}., e.g., "Sarah M."). Admin views may unmask to full identity per RBAC. Patients have no opt-in to expose full name in V1.
Alias-only Default · Active in V1
Reviewer shown as {first_name} {last_initial}. (e.g., "Sarah M.") on all public surfaces. Collisions within the same provider's list are deduplicated with a numeric suffix (Sarah M. 2, Sarah M. 3, …). Admin-seeded reviews use the admin-entered reviewer_display_name field.
Allow full name display Future expansion only
When enabled (future), patients may opt in to display their full name publicly. This option is disabled in V1 — enabling requires explicit product/legal approval and policy update.

⬆ Reviewer display policy change is audit-logged. Alias-only is the canonical default and cannot be disabled in V1.

Flagging Thresholds
Restricted Ranges
Configurable within policy-approved safe ranges only. Thresholds control auto-flagging for system moderation. Values outside safe ranges are rejected. Changes are audit-logged.
Duplicate Detection Threshold
Number of near-identical reviews within a time window before auto-flagging as duplicate. Safe range: 1–5.
reviews (1–5)
Spam Rate-Limit Window
Maximum number of reviews a single patient may submit within a rolling 24-hour period before triggering a rate-limit flag. Safe range: 1–10.
per 24h (1–10)
Keyword Flag Sensitivity
Number of flagged keyword matches required to trigger an auto-flag event on a review. Safe range: 1–10.
matches (1–10)

⬆ Values outside safe ranges are rejected by the system. Changes are audit-logged with before/after values.
